# Театр RAT — сайт

Главная с афишей, спектаклями, труппой и контактами, страница «Голосуй рублём» для чаевых актёрам через СБП, и админка для всего этого.

Адреса:

- `/` — главная: афиша с кнопками «Купить билет», спектакли, команда, о театре, контакты.
- `/golos` — «Голосуй рублём»: карточки актёров, перевод через СБП из любого банка.
- `/play.html?id=<id>` — страница спектакля: описание, даты, билеты, отзывы, бэкстейдж, «поделиться».
- `/admin` — админка: вкладки Афиша, Спектакли, Актёры, Отзывы, Бэкстейдж, О театре, Голосование.

Билеты сайт не продаёт сам. Кнопка «Купить билет» открывает виджет «Афиши» (tickets.afisha.ru) прямо на сайте — то же окно, что на teatrdoc.ru, оплата уходит площадке. Для этого в админке задаются ID партнёра площадки (Театр.doc — 37), ID спектакля и, при желании, ID сеансов; их видно в коде страницы teatrdoc.ru по слову openModal. Если ID не заданы, кнопка ведёт по обычной ссылке на страницу площадки.

Состав:

- `index.html` — главная. `play.html` — страница спектакля. `golos.html` — голосование. `admin.html` — админка.
- `assets/` — общие стили и скрипт главной и страниц спектаклей, обложка для превью ссылок `og-cover.png`, фавиконки.
- `render.php`, `index.php`, `play.php` — на PHP-хостинге подставляют в страницы Open Graph и разметку schema.org из `data/data.json`, чтобы Telegram, WhatsApp и Яндекс видели название, описание и постер. На GitHub Pages страницы отдаются как есть, с общей обложкой.
- `data/data.json` — все данные (театр, спектакли, показы, актёры), `photos/` — фото и постеры.
- `api.php` + `config.php` — бэкенд для PHP-хостинга (InfinityFree), вход по паролю.
- `.htaccess` — короткие адреса `/golos` и `/admin` на Apache; папки `golos/` и `admin/` делают то же на GitHub Pages.
- `fonts/` и `vendor/` — шрифты и скрипт QR-кода лежат на своём хостинге, ничего не грузится с Google и CDN.
- `server.js`, `Dockerfile` — вариант с Node.js для платного хостинга (не обязателен).
- `qr-print.pdf`, `qr-site.png`, `qr-site.svg` — QR-код на `/golos` для печати на сиденья.

Админка сама определяет, где запущена: с `server.js`, на PHP-хостинге или на GitHub Pages. Прошедшие показы на главной скрываются автоматически.

Что ещё умеет сайт:

- «Сегодня играем»: в день показа наверху появляется полоса с обратным отсчётом и кнопкой билетов, после начала спектакля она превращается в «Голосуй рублём».
- Стикеры на афише («Премьера», «Последний показ», «Мало билетов», «Sold out») ставятся галочками у показа. Sold out отключает кнопку покупки.
- «+ в календарь» у каждого показа, карта площадки по адресу из «О театре» (загружается по нажатию), кнопки «Поделиться» в Telegram и VK.
- Карточки труппы переворачиваются: на обороте «Роли» и «О себе» из вкладки «Актёры».
- Видео или фото в шапке главной: вкладка «О театре», MP4 до 10 МБ без звука.
- Фото при загрузке в админке сжимаются до 1600px и WebP прямо в браузере.

## Бесплатный вариант: GitHub Pages (рекомендуется)

Сервер не нужен. Сайт лежит в репозитории GitHub, а админка сохраняет данные и фото прямо в репозиторий через GitHub API. Ничего не засыпает, ничего не теряется, бесплатно.

Настройка один раз, минут 15:

1. Зарегистрироваться на github.com (если нет аккаунта).
2. Создать репозиторий, например `teatr`, публичный. Загрузить в него файлы `index.html`, `admin.html`, папки `data` и `photos` (кнопка «Add file → Upload files»). `node_modules`, `server.js` и остальное грузить не нужно, но и не помешает.
3. В репозитории: Settings → Pages → Build and deployment → Source: «Deploy from a branch», Branch: `main`, папка `/ (root)` → Save. Через минуту сайт откроется по адресу `https://<логин>.github.io/teatr/`.
4. Создать токен для админки: аватар → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
   - Repository access: «Only select repositories» → выбрать `teatr`.
   - Permissions → Repository permissions → Contents: «Read and write».
   - Expiration: максимальный срок (1 год), потом создать новый.
   - Скопировать токен, он показывается один раз.
5. Открыть `https://<логин>.github.io/teatr/admin.html`, ввести репозиторий `<логин>/teatr`, ветку `main` и токен. Токен хранится только в браузере этого устройства.

После «Сохранить» GitHub Pages пересобирает сайт, изменения видны через 1–2 минуты. Фото попадают в папку `photos` репозитория.

Токен даёт право писать в этот один репозиторий, больше ни к чему. Если токен утёк, его можно отозвать в тех же настройках GitHub.


## Афиша: импорт дат и живые остатки

- В админке у спектакля кнопка «Обновить даты из Афиши»: сервер запрашивает открытый API tickets.afisha.ru и создаёт или обновляет показы (дата, время, площадка, цена, номер сеанса). Если ID спектакля ещё не известен, можно вставить ссылку на страницу спектакля на teatrdoc.ru, ID найдётся сам.
- Наличие мест и минимальная цена обновляются автоматически: `api.php?a=afisha_status` (кэш 10 минут в `data/afisha-status.json`). Если мест нет, показ получает стикер «Sold out», если меньше 15 — «Мало билетов».
- Работает на InfinityFree и с `server.js`; на GitHub Pages сервера нет, там показываются данные из админки как есть.

## История версий, бэкап, посещения

- Каждое сохранение в админке кладёт предыдущую версию в `data/history/` (хранятся последние 20). Вкладка «История» показывает их и возвращает любую кнопкой «Вернуть»; текущее состояние при этом тоже уходит в историю.
- «Скачать всё архивом» (`api.php?a=backup`) отдаёт zip с `data/` и `photos/`. Хостинг резервных копий не делает, скачивайте регулярно.
- Счётчик посещений: страницы шлют `api.php?a=hit&p=…`, сервер считает просмотры и уникальных посетителей за день по усечённому хэшу IP+браузера (IP не хранится, cookie нет). Вкладка «Посещения» в админке.

## Фото и видео спектакля, ID из Афиши

- У спектакля в админке свой блок «Фото и видео»: загрузка сразу нескольких файлов (фото сжимаются, видео до 10 МБ), подписи и alt заполняются сами, порядок меняется стрелками. На странице спектакля они показываются слайдером, фото открываются в лайтбоксе.
- «Найти в Афише» подбирает ID спектакля по названию среди спектаклей площадки и подтягивает постер, если своего нет. «Обновить даты из Афиши» делает то же самостоятельно, если ID пустой.

## Черновики, проверка, обложки видео

- Галочка «Скрыть» у спектакля, показа, фото бэкстейджа, отзыва и у каждого фото/видео спектакля: запись остаётся в админке, но на сайт, в разметку и в sitemap не попадает. Показы и отзывы скрытого спектакля тоже не показываются.
- Вкладка «Проверка»: чего не хватает перед публикацией (постер, описание, ID Афиши, alt-тексты, обложки у видео, цена у показа, фото и СБП у актёров) и примерный вес страниц спектаклей по размерам файлов.
- Видео получает обложку автоматически при загрузке (кадр из ролика), на странице спектакля ролик грузится только после нажатия. У старых видео кнопка «Сделать обложку».
- На странице спектакля «Смотреть все фото» разворачивает слайдер в сетку; первый кадр предзагружается.
- Разметка для поиска: на странице спектакля ImageObject и VideoObject (и в PHP-версии, и в JS), в sitemap.xml картинки и видео спектаклей.

## Голосование, лайтбокс, сторис

- У актёра галочка «Показывать на странице «Голосуй рублём»»: без неё актёр остаётся в команде на главной, но не попадает в голосование.
- Фото с телефона поворачиваются по EXIF при сжатии в админке.
- Лайтбокс листается: стрелки, клавиши ←/→, свайп на телефоне, счётчик «3 / 12», Esc закрывает. Группа — все фото того же блока.
- На странице спектакля кнопка «Картинка «Я иду»»: собирает картинку 1080×1920 для сторис с постером, названием, датой и адресом сайта; на телефоне «Поделиться» через системное меню, на компьютере «Скачать».

## Автоподписи к фото и голоса актёров

- При загрузке фото в «Бэкстейдж» подпись и alt-текст заполняются сами, без внешних сервисов: по выбранному спектаклю, дате съёмки из EXIF (для JPEG с телефона), ориентации и тональности кадра. Кнопка «Придумать подпись заново» перебирает варианты. Всё правится руками.
- У спектакля можно добавить «голоса актёров»: аудио 30–60 секунд (mp3, m4a, ogg, wav до 10 МБ), имя и о чём. На странице спектакля появляется блок «Голоса» с плеером.

## Печать, 404, поисковики

- `poster.html` — афиша А4 из текущих данных с QR на сайт, кнопка «Печать / сохранить PDF». Ссылка есть в шапке админки.
- `404.html` — страница «не найдено» в стиле сайта (`.htaccess` → `ErrorDocument`, GitHub Pages подхватывает сам).
- `robots.txt`, `sitemap.xml` (на PHP-хостинге генерируется `sitemap.php` из данных). После деплоя: добавить сайт в Яндекс.Вебмастер (webmaster.yandex.ru, подтверждение через мета-тег или файл) и завести карточку в Яндекс.Бизнесе (business.yandex.ru) с ссылкой на сайт.

## Бесплатный вариант 2: PHP-хостинг (InfinityFree), вход по паролю

Подходит, если не хочется возиться с токенами GitHub. Работает на любом хостинге с PHP 7.4+, включая бесплатный InfinityFree.

1. Зарегистрироваться на infinityfree.com → Create Account → выбрать бесплатный поддомен (например `rat-teatr.rf.gd`) или указать свой домен. Подождать, пока аккаунт активируется (обычно минуты).
2. Открыть `config.example.php`, сохранить копию как `config.php` и вписать свой пароль вместо `смените-меня`. Пока стоит значение по умолчанию, вход в админку закрыт.
3. В панели InfinityFree открыть File Manager (или подключиться по FTP через FileZilla, данные FTP показаны в панели) и зайти в папку `htdocs`. Удалить оттуда стандартные файлы.
4. Загрузить в `htdocs`: `index.html`, `play.html`, `golos.html`, `admin.html`, `api.php`, `render.php`, `index.php`, `play.php`, `config.php`, `.htaccess`, папки `assets`, `fonts`, `vendor`, `data` с `data.json` и пустую папку `photos`.
5. Открыть `https://ваш-домен/admin.html`, ввести пароль.

Сохранение работает сразу, без задержки. Фото складываются в папку `photos` на хостинге.

Ограничения InfinityFree: файл до 10 МБ, 5 ГБ места, 50 000 обращений в день. Бэкапов у них нет, поэтому раз в сезон скачивайте `data/data.json` и папку `photos` через File Manager. Перед печатью QR проверьте, что сайт открывается с мобильного интернета разных операторов: InfinityFree бывает недоступен из России.

Важно: `config.php` с настоящим паролем не должен попадать в репозиторий GitHub, он исключён через `.gitignore`. Пароль задаётся только на хостинге.

Пароль можно сменить прямо из админки: вкладка «История» → «Пароль админки». Новый пароль хранится в виде хэша в `data/password.json` и имеет приоритет над `config.php`; в бэкап и в git этот файл не попадает. Чтобы сбросить забытый пароль, удалите `data/password.json` на хостинге — снова заработает пароль из `config.php` (для Node — из `ADMIN_PASSWORD`).

## Вариант с сервером (платный хостинг)

Нужен, только если не хочется зависеть от GitHub. Нужен Node.js 18 или новее.

```bash
npm install
ADMIN_PASSWORD=придумайте-пароль node server.js
```

Сайт: http://localhost:3000, админка: http://localhost:3000/admin.

Если `ADMIN_PASSWORD` не задан, сервер сам сгенерирует пароль и сохранит его в `data/password.txt`. Порт задаётся переменной `PORT`. Смена пароля из админки работает и здесь (`data/password.json`).

## Эффекты и «панк»-анимации

Всё на чистом CSS, скрипт только расставляет классы; при `prefers-reduced-motion` всё выключено.

- Заставка на всех страницах: старый телевизор с помехами, на экране вспыхивает «Театр RAT», камера влетает в экран, вспышка — и открывается сайт (~3 с). Показывается при открытии сайта с любой страницы и при обновлении страницы; при переходах по ссылкам внутри сайта не повторяется (иначе она шла бы после каждого клика поверх перехода-«кинескопа»). Клик пропускает. Разметка и мини-скрипт лежат в начале `index.html`, `play.html`, `golos.html` (одинаковые), стили — `assets/intro.css`, корпус — фото `assets/tv.webp` с вырезанным экраном (анимированный экран лежит под картинкой).
- Глитч заголовков: раз в 3 секунды заголовок секции рвётся полосками со сдвигом красного и голубого канала (`h2.sec .gl`).
- Стикеры «Премьера», «Последний», «Осталось N мест» шлёпаются на карточку при появлении, карточка вздрагивает. Скотч на карточках отклеивается при наведении.
- Курсор-точка (была раньше) теперь оставляет след баллончика — только для мыши.
- Бегущая строка управляется скриптом: разгоняется, пока страницу крутят, и успокаивается до 80 px/с. Крыса на ленте кликабельна: пищит (синтез Web Audio, без файлов) и убегает.
- Переход между страницами: старая «выключается» как кинескоп — схлопывается в яркую полосу, затем сверху опускается новая с рваным краем (View Transitions API, Chrome 126+ и Safari 18.2+; в остальных — обычный переход).
- Плёночное зерно и полоски поверх видео в шапке; постеры при наведении мигают как старый телевизор.
- Кнопка «Купить билет» вздрагивает один раз, если до показа меньше трёх дней.

## PWA, пуш-уведомления и лист ожидания

- `manifest.webmanifest` + `sw.js`: сайт ставится на телефон как приложение (Chrome сам предложит, на iPhone — Поделиться → На экран «Домой»), афиша открывается без сети из кэша. Версия кэша — константа `VERSION` в `sw.js`, менять вместе с `?v=`.
- «🔔 напомнить за день» у каждого показа и «сообщить, если появятся» на аншлаге. Подписка браузера хранится в `data/push.json` без личных данных; почта из листа ожидания — в `data/waitlist.json`.
- Пуш уходит без текста (только «тычок» с подписью VAPID), service worker сам спрашивает у `api.php?a=push_msg`, что показать — поэтому не нужны библиотеки шифрования. VAPID-ключи создаются автоматически в `data/push-keys.json` (не публиковать, в бэкап не попадает).
- Рассылка запускается вызовом `api.php?a=push_send&key=…` (адрес показан в админке на вкладке «Уведомления»). Хостинг без cron, поэтому поставьте этот адрес на бесплатный [cron-job.org](https://cron-job.org) раз в час, или нажимайте «Разослать сейчас» в админке.
- iPhone показывает пуши только для сайта, добавленного на экран «Домой» (iOS 16.4+). Письма отправляет `mail()` хостинга — на InfinityFree работает нестабильно, пуш надёжнее. В Node-версии письма только пишутся в лог.
- В превью Telegram/VK страница спектакля отдаёт `og:video` (первое видео из медиа), главная — видео шапки.

## Отзывы с сайта, календарь, превью для соцсетей, 404

- **Отзыв с сайта.** Форма «Оставить отзыв» под отзывами на главной и на странице спектакля. Отзыв уходит в `api.php?a=review` (Node: `POST /api/review`) и попадает в админку черновиком с пометкой «пришёл с сайта»; на вкладке «Отзывы» виден счётчик новых. Защита: скрытое поле-ловушка для ботов, минимум 20 символов, без ссылок, не больше 5 отзывов в день с одного адреса. Если отзыв пришёл, пока админка была открыта, сервер подмешивает его при сохранении (параметр `since`), чтобы не затереть.
- **Подписка на календарь.** `calendar.php` (адрес `/calendar.ics`, Node: `/calendar.ics`) отдаёт живой iCalendar со всеми показами за последние 30 дней и вперёд, с напоминанием за сутки. Ссылка «Подписаться на календарь театра» стоит под афишей: `webcal://` открывает подписку в Apple/Android-календаре, для Google Calendar есть кнопка «скопировать ссылку» («Другие календари → Добавить по URL»). Календарь обновляется у зрителя сам.
- **Картинка-превью (og:image).** `og.php?id=<спектакль>` рисует PNG 1200×630 через GD: постер, название, жанр, ближайший показ и стикер «Осталось N мест» (по кэшу остатков Афиши). `og.php` без id — карточка театра с ближайшим показом. Результат кэшируется в `data/og/` и перерисовывается, когда меняются постер, дата или остаток. `render.php` подставляет эти адреса в `og:image`. Шрифты для GD лежат в `fonts/og/` (TTF, собраны из тех же woff2). В Node-версии превью статичное.
- **404 «Нет сигнала».** `404.html` — экран телевизора без сигнала: помехи, цветные полосы, мигающая надпись, кнопка «Вернуться в эфир»; шипение включается кнопкой (Web Audio, без файлов).
- **«Что изменилось»** во вкладке «История»: сравнение версии с текущим состоянием (верхняя строка) или со следующей версией — какие записи добавлены, удалены, какие поля изменились. Ниже — «Журнал обновлений сайта» из `changelog.json` (что и когда добавлялось в сам сайт).

## Скорость (Lighthouse)

Проверено локально Lighthouse 12 (мобильный профиль). Что сделано по итогам: заставка стартует только после загрузки картинки телевизора и пропускается, если та не пришла за 0,9 с (на медленной сети не держим чёрный экран); картинка телевизора и основные шрифты предзагружаются; `site.js` подключён с `defer`; запасные шрифты с подогнанными метриками (`fonts.css`), чтобы текст не прыгал при подмене; место под блок «ближайший показ» зарезервировано; скрытые до прокрутки блоки помечены `visibility:hidden`; мелкие ссылки «в календарь» и «напомнить» получили высоту 24 px; бегущая полоса на экране телевизора анимируется через transform. Оставшийся резерв — это сам объём `site.css`/`site.js` и хостинг: InfinityFree отдаёт файлы медленно и вставляет проверку браузера.

## Страницы актёров, нижняя панель, ролики и прочее по сайту

- **Страницы актёров** `actor.html?id=<слаг>` (на хостинге `actor.php` подставляет OG и schema.org Person). Слаг делается из имени транслитом (`Иван Петров` → `ivan-petrov`) одинаково в `site.js`, `render.php` и `golos.html`. Страница существует, только если у актёра есть фото и заполнено «О себе» или «Роли»; иначе ссылки нет и адрес отдаёт «Такой страницы нет». На странице: фото, амплуа, роли, «О себе», кнопка «Голосуй рублём» (ведёт на карточку актёра на /golos по якорю), спектакли, где актёр упомянут в поле «Кто играет» (ищется имя или фамилия), его голоса из всех спектаклей, фото бэкстейджа, где он отмечен, и остальная команда. На обороте карточки в «Команде» появляется ссылка «страница →». Страницы попадают в sitemap.
- **Кто на фото.** У фото бэкстейджа в админке галочки с актёрами (`gallery[].actors`, имена). В лайтбоксе подпись «на фото: …», фото попадают на страницы отмеченных актёров.
- **Нижняя панель на телефоне** (`R.mobileBar`, ширина до 700 px): Афиша · Билеты · Голосуй. «Билеты» нажимает ближайшую живую кнопку покупки на странице, иначе ведёт к афише. На странице спектакля панель становится **липкой кнопкой покупки**: «Купить билет · 12 сен · 20:00 · от 1500 ₽ · осталось 12» (`R.stickyBuyText`), при аншлаге — «Билетов нет · лист ожидания». Панель прячется, пока открыт виджет Афиши или идёт заставка.
- **«Наверх»** (`R.toTop`): крыса на канате справа внизу, появляется после двух экранов, по клику лезет вверх и страница уезжает к началу.
- **Полоса прокрутки** (`R.scrollProgress`): кислотная линия сверху, по ней бежит крыса.
- **Фильтр стены бэкстейджа** по спектаклям (`R.wallFilter`): «все · Мёртвая волна · ПОХ», кнопки появляются, если у фото проставлены спектакли. Лайтбокс листает только видимые.
- **Ролики** (`R.reel`): лента вертикальных видео из медиа всех спектаклей в блоке «Бэкстейдж», карточки 9:16 листаются со snap. Видео стартует без звука, когда карточка на 60 % в кадре, и ставится на паузу, уходя из него; касание включает звук (у остальных выключает). Если видео нет, блок скрыт.
- **Скелеты**: пока грузится `data.json`, на месте афиши, спектаклей, команды и стены серые «бумажки» с переливом (`.sk`), секции не появляются рывком.

## Админка

Длинный текст в однострочном поле (состав, роли, адрес и т.п.) виден целиком: поле само становится многострочным и растёт по высоте, Enter в нём не переводит строку; обычные textarea тоже растут под содержимое. Админка подстроена под телефон: на узком экране вкладки уезжают вниз под большой палец, кнопки не меньше 44 px, поля 16 px (iPhone не зумит), у фото и медиа есть кнопка «📷 Снять» — снимок с камеры сразу уходит на сайт, а записи (даты, спектакли, актёры, фото) переставляются перетаскиванием за ручку «≡».

- Спектакль: театр, название, даты в шапке.
- Каждый актёр: имя, сцена/роль, описание, фото (JPG/PNG/WebP до 8 МБ), ссылка СБП, телефон и банк для запасного способа.
- Кнопки «↑ ↓» меняют порядок карточек, «Удалить» убирает актёра, «+ Добавить актёра» создаёт новую карточку.
- Под полем ссылки СБП подсказка: зелёная «ок», если это `https://qr.nspk.ru/...`, красная, если поле пустое или ссылка другого вида.
- Изменения попадают на сайт после кнопки «Сохранить» внизу экрана.

## Где взять ссылку СБП (qr.nspk.ru)

Каждый актёр делает это один раз в своём банковском приложении:

- **Сбербанк Онлайн**: Профиль (аватар) → «Получить перевод по QR-коду» → вкладка **СБП** → «Поделиться» → скопировать ссылку.
- **Т-Банк**: Главная → «Мой QR» / «Получить перевод по QR» → СБП → «Поделиться ссылкой».
- **Альфа-Банк**: Платежи → «Получить перевод по QR» (СБП) → «Поделиться».
- **ВТБ, Райффайзен, Газпромбанк и др.**: раздел «Переводы» → «Получить перевод по QR (СБП)».

Нужна именно ссылка `https://qr.nspk.ru/...`. Ссылки вида `sberbank.com/sms/...` — внутренний QR Сбера, он работает только у клиентов Сбера.

Пока ссылка не добавлена, кнопка на карточке неактивна и подписана «ссылка СБП ещё не добавлена».

## Хостинг для варианта с сервером

Нужен хостинг с Node.js. Бесплатных с сохранением файлов практически нет: Render бесплатен, но засыпает после 15 минут простоя и стирает загруженные фото при перезапуске. Платные варианты от 170 ₽ в месяц (Amvera) или VPS.

Варианты:

1. **Timeweb Cloud / Beget / Reg.ru** — тариф с Node.js или Docker. Загрузить папку, задать переменные `ADMIN_PASSWORD` и `PORT`, команда запуска `node server.js`.
2. **Любой VPS** (Ubuntu): установить Node.js, скопировать папку, запустить через pm2:
   ```bash
   npm install
   ADMIN_PASSWORD=пароль pm2 start server.js --name teatr
   ```
   Перед сервером поставить nginx или Caddy с HTTPS (Caddy делает сертификат сам).
3. **Docker**:
   ```bash
   docker build -t teatr .
   docker run -d -p 3000:3000 -e ADMIN_PASSWORD=пароль -v teatr-data:/app/data -v teatr-photos:/app/photos teatr
   ```

Важно: папки `data` и `photos` — это всё содержимое сайта. Их нужно бэкапить и не терять при переустановке.

Затем сгенерировать один QR-код на адрес сайта (любой онлайн-генератор) и распечатать его на сиденья вместо пяти сберовских.

## Как страница берёт данные

По порядку: сначала `/api/data` (если запущен `server.js`), затем файл `data/data.json` (GitHub Pages, PHP-хостинг и любая статика), затем `api.php?a=data`, затем блок «НАСТРОЙКИ» внутри `index.html` (если открыть файл напрямую).
