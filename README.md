# Театр RAT — сайт

Главная с афишей, спектаклями, труппой и контактами, страница «Голосуй рублём» для чаевых актёрам через СБП, и админка для всего этого.

Адреса:

- `/` — главная: афиша с кнопками «Купить билет», спектакли, команда, о театре, контакты.
- `/golos` — «Голосуй рублём»: карточки актёров, перевод через СБП из любого банка.
- `/play.html?id=<id>` — страница спектакля: описание, даты, билеты, отзывы, бэкстейдж, «поделиться».
- `/admin` — админка: вкладки Афиша, Спектакли, Актёры, Отзывы, Бэкстейдж, О театре, Голосование.

Билеты сайт не продаёт сам. Кнопка «Купить билет» открывает виджет «Афиши» (tickets.afisha.ru) прямо на сайте — то же окно, что на teatrdoc.ru, оплата уходит площадке. Для этого в админке задаются ID партнёра площадки (Театр.doc — 37), ID спектакля и, при желании, ID сеансов; их видно в коде страницы teatrdoc.ru по слову openModal. Если ID не заданы, кнопка ведёт по обычной ссылке на страницу площадки.

Состав:

- `index.html` — главная. `play.html` — страница спектакля. `golos.html` — голосование. `admin.html` — админка.
- `assets/` — общие стили и скрипт главной и страниц спектаклей, обложка для превью ссылок `og-cover.png`, фавиконки.
- `render.php`, `index.php`, `play.php` — на PHP-хостинге подставляют в страницы Open Graph и разметку schema.org из `data/data.json`, чтобы Telegram, WhatsApp и Яндекс видели название, описание и постер. На GitHub Pages страницы отдаются как есть, с общей обложкой.
- `data/data.json` — все данные (театр, спектакли, показы, актёры), `photos/` — фото и постеры.
- `api.php` + `config.php` — бэкенд для PHP-хостинга (InfinityFree), вход по паролю.
- `.htaccess` — короткие адреса `/golos` и `/admin` на Apache; папки `golos/` и `admin/` делают то же на GitHub Pages.
- `fonts/` и `vendor/` — шрифты и скрипт QR-кода лежат на своём хостинге, ничего не грузится с Google и CDN.
- `server.js`, `Dockerfile` — вариант с Node.js для платного хостинга (не обязателен).
- `qr-print.pdf`, `qr-site.png`, `qr-site.svg` — QR-код на `/golos` для печати на сиденья.

Админка сама определяет, где запущена: с `server.js`, на PHP-хостинге или на GitHub Pages. Прошедшие показы на главной скрываются автоматически.

Что ещё умеет сайт:

- «Сегодня играем»: в день показа наверху появляется полоса с обратным отсчётом и кнопкой билетов, после начала спектакля она превращается в «Голосуй рублём».
- Стикеры на афише («Премьера», «Последний показ», «Мало билетов», «Sold out») ставятся галочками у показа. Sold out отключает кнопку покупки.
- «+ в календарь» у каждого показа, карта площадки по адресу из «О театре» (загружается по нажатию), кнопки «Поделиться» в Telegram и VK.
- Карточки труппы переворачиваются: на обороте «Роли» и «О себе» из вкладки «Актёры».
- Видео или фото в шапке главной: вкладка «О театре», MP4 до 10 МБ без звука.
- Фото при загрузке в админке сжимаются до 1600px и WebP прямо в браузере.

## Бесплатный вариант: GitHub Pages (рекомендуется)

Сервер не нужен. Сайт лежит в репозитории GitHub, а админка сохраняет данные и фото прямо в репозиторий через GitHub API. Ничего не засыпает, ничего не теряется, бесплатно.

Настройка один раз, минут 15:

1. Зарегистрироваться на github.com (если нет аккаунта).
2. Создать репозиторий, например `teatr`, публичный. Загрузить в него файлы `index.html`, `admin.html`, папки `data` и `photos` (кнопка «Add file → Upload files»). `node_modules`, `server.js` и остальное грузить не нужно, но и не помешает.
3. В репозитории: Settings → Pages → Build and deployment → Source: «Deploy from a branch», Branch: `main`, папка `/ (root)` → Save. Через минуту сайт откроется по адресу `https://<логин>.github.io/teatr/`.
4. Создать токен для админки: аватар → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
   - Repository access: «Only select repositories» → выбрать `teatr`.
   - Permissions → Repository permissions → Contents: «Read and write».
   - Expiration: максимальный срок (1 год), потом создать новый.
   - Скопировать токен, он показывается один раз.
5. Открыть `https://<логин>.github.io/teatr/admin.html`, ввести репозиторий `<логин>/teatr`, ветку `main` и токен. Токен хранится только в браузере этого устройства.

После «Сохранить» GitHub Pages пересобирает сайт, изменения видны через 1–2 минуты. Фото попадают в папку `photos` репозитория.

Токен даёт право писать в этот один репозиторий, больше ни к чему. Если токен утёк, его можно отозвать в тех же настройках GitHub.


## Афиша: импорт дат и живые остатки

- В админке у спектакля кнопка «Обновить даты из Афиши»: сервер запрашивает открытый API tickets.afisha.ru и создаёт или обновляет показы (дата, время, площадка, цена, номер сеанса). Если ID спектакля ещё не известен, можно вставить ссылку на страницу спектакля на teatrdoc.ru, ID найдётся сам.
- Наличие мест и минимальная цена обновляются автоматически: `api.php?a=afisha_status` (кэш 10 минут в `data/afisha-status.json`). Если мест нет, показ получает стикер «Sold out», если меньше 15 — «Мало билетов».
- Работает на InfinityFree и с `server.js`; на GitHub Pages сервера нет, там показываются данные из админки как есть.

## История версий, бэкап, посещения

- Каждое сохранение в админке кладёт предыдущую версию в `data/history/` (хранятся последние 20). Вкладка «История» показывает их и возвращает любую кнопкой «Вернуть»; текущее состояние при этом тоже уходит в историю.
- «Скачать всё архивом» (`api.php?a=backup`) отдаёт zip с `data/` и `photos/`. Хостинг резервных копий не делает, скачивайте регулярно.
- Счётчик посещений: страницы шлют `api.php?a=hit&p=…`, сервер считает просмотры и уникальных посетителей за день по усечённому хэшу IP+браузера (IP не хранится, cookie нет). Вкладка «Посещения» в админке.

## Печать, 404, поисковики

- `poster.html` — афиша А4 из текущих данных с QR на сайт, кнопка «Печать / сохранить PDF». Ссылка есть в шапке админки.
- `404.html` — страница «не найдено» в стиле сайта (`.htaccess` → `ErrorDocument`, GitHub Pages подхватывает сам).
- `robots.txt`, `sitemap.xml` (на PHP-хостинге генерируется `sitemap.php` из данных). После деплоя: добавить сайт в Яндекс.Вебмастер (webmaster.yandex.ru, подтверждение через мета-тег или файл) и завести карточку в Яндекс.Бизнесе (business.yandex.ru) с ссылкой на сайт.

## Бесплатный вариант 2: PHP-хостинг (InfinityFree), вход по паролю

Подходит, если не хочется возиться с токенами GitHub. Работает на любом хостинге с PHP 7.4+, включая бесплатный InfinityFree.

1. Зарегистрироваться на infinityfree.com → Create Account → выбрать бесплатный поддомен (например `rat-teatr.rf.gd`) или указать свой домен. Подождать, пока аккаунт активируется (обычно минуты).
2. Открыть `config.example.php`, сохранить копию как `config.php` и вписать свой пароль вместо `смените-меня`. Пока стоит значение по умолчанию, вход в админку закрыт.
3. В панели InfinityFree открыть File Manager (или подключиться по FTP через FileZilla, данные FTP показаны в панели) и зайти в папку `htdocs`. Удалить оттуда стандартные файлы.
4. Загрузить в `htdocs`: `index.html`, `play.html`, `golos.html`, `admin.html`, `api.php`, `render.php`, `index.php`, `play.php`, `config.php`, `.htaccess`, папки `assets`, `fonts`, `vendor`, `data` с `data.json` и пустую папку `photos`.
5. Открыть `https://ваш-домен/admin.html`, ввести пароль.

Сохранение работает сразу, без задержки. Фото складываются в папку `photos` на хостинге.

Ограничения InfinityFree: файл до 10 МБ, 5 ГБ места, 50 000 обращений в день. Бэкапов у них нет, поэтому раз в сезон скачивайте `data/data.json` и папку `photos` через File Manager. Перед печатью QR проверьте, что сайт открывается с мобильного интернета разных операторов: InfinityFree бывает недоступен из России.

Важно: `config.php` с настоящим паролем не должен попадать в репозиторий GitHub, он исключён через `.gitignore`. Пароль задаётся только на хостинге.

## Вариант с сервером (платный хостинг)

Нужен, только если не хочется зависеть от GitHub. Нужен Node.js 18 или новее.

```bash
npm install
ADMIN_PASSWORD=придумайте-пароль node server.js
```

Сайт: http://localhost:3000, админка: http://localhost:3000/admin.

Если `ADMIN_PASSWORD` не задан, сервер сам сгенерирует пароль и сохранит его в `data/password.txt`. Порт задаётся переменной `PORT`.

## Админка

- Спектакль: театр, название, даты в шапке.
- Каждый актёр: имя, сцена/роль, описание, фото (JPG/PNG/WebP до 8 МБ), ссылка СБП, телефон и банк для запасного способа.
- Кнопки «↑ ↓» меняют порядок карточек, «Удалить» убирает актёра, «+ Добавить актёра» создаёт новую карточку.
- Под полем ссылки СБП подсказка: зелёная «ок», если это `https://qr.nspk.ru/...`, красная, если поле пустое или ссылка другого вида.
- Изменения попадают на сайт после кнопки «Сохранить» внизу экрана.

## Где взять ссылку СБП (qr.nspk.ru)

Каждый актёр делает это один раз в своём банковском приложении:

- **Сбербанк Онлайн**: Профиль (аватар) → «Получить перевод по QR-коду» → вкладка **СБП** → «Поделиться» → скопировать ссылку.
- **Т-Банк**: Главная → «Мой QR» / «Получить перевод по QR» → СБП → «Поделиться ссылкой».
- **Альфа-Банк**: Платежи → «Получить перевод по QR» (СБП) → «Поделиться».
- **ВТБ, Райффайзен, Газпромбанк и др.**: раздел «Переводы» → «Получить перевод по QR (СБП)».

Нужна именно ссылка `https://qr.nspk.ru/...`. Ссылки вида `sberbank.com/sms/...` — внутренний QR Сбера, он работает только у клиентов Сбера.

Пока ссылка не добавлена, кнопка на карточке неактивна и подписана «ссылка СБП ещё не добавлена».

## Хостинг для варианта с сервером

Нужен хостинг с Node.js. Бесплатных с сохранением файлов практически нет: Render бесплатен, но засыпает после 15 минут простоя и стирает загруженные фото при перезапуске. Платные варианты от 170 ₽ в месяц (Amvera) или VPS.

Варианты:

1. **Timeweb Cloud / Beget / Reg.ru** — тариф с Node.js или Docker. Загрузить папку, задать переменные `ADMIN_PASSWORD` и `PORT`, команда запуска `node server.js`.
2. **Любой VPS** (Ubuntu): установить Node.js, скопировать папку, запустить через pm2:
   ```bash
   npm install
   ADMIN_PASSWORD=пароль pm2 start server.js --name teatr
   ```
   Перед сервером поставить nginx или Caddy с HTTPS (Caddy делает сертификат сам).
3. **Docker**:
   ```bash
   docker build -t teatr .
   docker run -d -p 3000:3000 -e ADMIN_PASSWORD=пароль -v teatr-data:/app/data -v teatr-photos:/app/photos teatr
   ```

Важно: папки `data` и `photos` — это всё содержимое сайта. Их нужно бэкапить и не терять при переустановке.

Затем сгенерировать один QR-код на адрес сайта (любой онлайн-генератор) и распечатать его на сиденья вместо пяти сберовских.

## Как страница берёт данные

По порядку: сначала `/api/data` (если запущен `server.js`), затем файл `data/data.json` (GitHub Pages, PHP-хостинг и любая статика), затем `api.php?a=data`, затем блок «НАСТРОЙКИ» внутри `index.html` (если открыть файл напрямую).
